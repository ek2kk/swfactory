# Архив и остановка задач

Архивирование и подтверждение остановки — независимые состояния.
`POST /api/projects/:projectId/tasks/:taskId/archive` принимает `request_id`
и `state_version`. Ownership и версия проверяются до побочных эффектов.
Одна транзакция сохраняет `archived=1`, блокирует новые действия, отзывает
pending human requests и queued/sending chat. Сразу после этого контроллер
снимает scheduler jobs и начинает остановку. Ответ не ждёт окончания процессов.
Повтор запроса возвращает сохранённый ответ без повторного архивирования.

SQLite v14 добавляет `archived`. `snapshot.tasks` содержит доску,
`archived_tasks` — архив. SSE обновляет обе вкладки. Уже удалённые в v13
карточки доступны в архиве; прежние failed-удаления остаются на доске,
пока пользователь явно не архивирует их. История и файлы не удаляются.

Существующий `deletion_state` сохраняет результат остановки: `stopping`,
`failed` (не подтверждена), `deleted` (подтверждена). Имена полей и старый
`/delete` сохранены для совместимости. Новая кнопка использует `/archive`,
повтор остановки в архиве — `/stop`. Архивирование не очищает
`stop_unverified` или `execution_unverified`, не является ручной сверкой
и не освобождает слот незавершённого callback/известной process group.
Поздние callbacks не возобновляют pipeline и не возвращают карточку на доску.

Остановка посылает TERM известным POSIX process groups, затем KILL через
500 ms; до 5 s ждёт исчезновения известных групп и callbacks. `ps` не доказывает
отсутствие orphaned detached-потомков. Каждый зарегистрированный процесс
сохраняет `stop_unverified`; исчезновение известной группы его не снимает.
При неопределённости архив показывает предупреждение и данные для сверки.
Историческое исполнение баз до v13 также помечается неподтверждённым.
После restart процессам прежнего backend автоматически не отправляются сигналы.

`/stop` позволяет повторить остановку без текста подтверждения.
Необязательный `reconciliation` (20–4096 символов) означает фактическую
ручную проверку отсутствия процессов и remote результата. Она сохраняется
в `task.stop-verified-by-human`; backend не выдаёт её за собственное доказательство.
Проверка известных групп выполняется и после ручного подтверждения.

В архиве доступны описание и редакции, сообщения, runs, отчёты и redacted логи.
Read-only API проверяет project/task/run ownership; команды по-прежнему запрещены.
Неизвестная remote-операция остаётся unknown, доступный PR URL сохраняется.
Архивирование не отменяет отправленный push/create и не повторяет публикацию.

## Проверка

`npm run check` на Node.js 24. Process tests требуют доступа к read-only `ps`.
Regression tests покрывают старую NeedsHuman-задачу с неподтверждённой остановкой,
немедленное скрытие при незавершённом callback, сохранение scheduler slot,
request replay/version/ownership, read-only историю, два SSE клиента,
миграцию v13 и restart, повтор остановки и ручную сверку.

Для GUI используйте отдельный backend и временную базу: проверьте отмену
подтверждения, архивирование из detail, предупреждение об остановке, архивную
историю, повтор остановки без ручной сверки и сохранение архива после reload.
Не используйте пользовательские карточки для smoke-проверки.
